# PUS-C independent secondary-header evidence

## Normative source

The v2.0.0 PUS-C telecommand evidence is traced to ECSS-E-ST-70-41C, 15 April 2016, clause 7.4.4.1.

Figure 7-9 defines the telecommand packet secondary-header leading fields as:

- TC packet PUS version number: 4 bits;
- acknowledgement flags: 4 bits;
- service type ID: 8 bits;
- message subtype ID: 8 bits;
- source ID: 16 bits;
- optional mission-declared spare field.

Requirement 7.4.4.1.c requires the TC packet PUS version number to be 2. Requirement 7.4.4.1.d assigns acknowledgement bits 3 through 0 respectively to successful acceptance, start, progress, and completion reporting requests. Each bit is independently set to 1 when that report is requested and 0 otherwise.

## Independent acknowledgement matrix

For the fixed evidence values service type `0x11`, message subtype `0x01`, and source ID `0x1234`, the standard field definition therefore gives the following literal five-octet PUS-C TC secondary-header vectors before any optional spare field:

`test/src/testGroupEvidence.cpp` contains this matrix as literal independent expected bytes. For every row it checks encoder output byte-for-byte and independently decodes the literal vector to verify acknowledgement flags, service type, subtype, and source ID.

The expected first octet is not generated by the implementation under test. It is fixed evidence derived directly from the standard's four-bit PUS version field followed by its four independently selectable acknowledgement bits.

## Other PUS-C evidence

The existing PUS tests and CLI integration retain independent evidence for:

- PUS-C TC and TM fixed secondary-header layouts;
- the fixed two-octet TC source ID and TM destination ID;
- PUS-C TM message-type counter and time-reference status;
- TM without a timestamp;
- TM with numeric CUC timestamp tailoring;
- full Space Packets with packet-level CRC16;
- reserved/version, direction, identifier, spare-field, and timestamp failures.

The release compliance matrices reference this document together with the concrete test sources rather than treating encoder/decoder round-trip behavior alone as independent conformance evidence.
